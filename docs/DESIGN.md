# Design notes

How the Medusify app looks and why. Read this before you add or change a screen. The app is an iPhone-first web
app for Medusa v2 merchants. It replaces something they open several times a day, so it follows iOS conventions
instead of inventing its own.

The values below come from `docs/tools/tokens.json`. The blocks between `<!-- GEN:... -->` and `<!-- /GEN:... -->` are
generated by `node docs/tools/build-tokens.mjs`; do not edit them by hand. The same run writes `docs/mocks/tokens.css`.
`node docs/tools/build-tokens.mjs --check` exits with 1 if a contrast pair misses its target and with 2 if a hex value
in `tokens.css` or in this file is not in `tokens.json`. The app itself reads its tokens from `pwa/src/styles/app.css`.

## Direction

- **Use.** One hand, thumb at the bottom, a session of under a minute, often right after a push notification. Light
  and dark mode are equal. Everything that matters sits in the lower half of the screen.
- **Reference.** The iOS system apps, mainly Mail and Wallet: grouped inset lists on a gray background, large titles,
  hairlines instead of borders, one tint color. Familiarity is the quality bar for an app that people use daily.
- **Type.** System font stack (`-apple-system, system-ui, sans-serif`). No web font file.
- **Color.** Cool neutrals plus one petrol tint. Status is always text plus a symbol, never color alone.
- **Density.** Medium. Rows are 56 px with two lines of text, page margins are 16 px.
- **Where the identity sits.** In data and attribution, not in chrome: a shop switcher in the navigation bar, a
  monogram per shop, and a quiet/loud split. Done is quiet (gray, check mark), open is loud (amber "To ship"). On the
  start screen the shipping band is the only filled element. There are no charts and no promo cards. Revenue is a list
  with one row per currency, and currencies are never added together.
- **Not a clone of another admin app.** No colors, logos, icons or texts of other commerce admin apps.

## Typography

Sizes are in `rem` and follow the iOS text styles. The root size follows the reader's setting:

```css
html { font-size: 17px; }
@supports (font: -apple-system-body) {
  html { font: -apple-system-body; font-family: -apple-system, system-ui, sans-serif; }
}
```

- Amounts, quantities, order numbers and times use `font-variant-numeric: tabular-nums` (class `.num`) and are right
  aligned in columns. Format currencies with `Intl.NumberFormat(locale, { style: "currency", currency })` so the
  symbol stays with the number.
- Headings use sentence case. No uppercase labels, no letter spacing on text, no small label above a heading.
- The smallest size is 11 px (`caption-2`, tab labels only). Running text is never smaller than `footnote`.
- Inputs render at 16 px or more, otherwise iOS zooms on focus.
- The mocks use Noto Sans as a stand-in because WebKit on Linux has no SF. Noto Sans is wider, so a layout that fits
  in the mocks fits on the device. Real glyph shapes and line breaks on an iPhone are not verified.

## Color

Semantic names as in iOS (background, row, label, separator) plus **one** tint. Dark mode has its own tint value, not an
inverted light one.

- Tint is for actions, selection, focus and links. Never for decoration or large areas.
- Status is text plus symbol: amber "To ship" with a parcel, gray "Shipped" with a check mark, red "Canceled" with a cross.
- Shop monograms use six fixed colors, the same in light and dark, with white letters (each at least 4.5:1). The color
  only helps recognition. The shop name is always next to it or in the accessible label.
- Red surfaces only for the refund confirmation and for errors.
- Bars use `color-mix(in srgb, var(--bg) 82%, transparent)` with `backdrop-filter: blur(20px) saturate(1.4)` and a
  hairline. With "Reduce Transparency" or without `backdrop-filter` they fall back to a solid `--bg`.

### Contrast

WCAG 2.x ratios, computed from `tokens.json`. Text needs 4.5:1, controls and focus indicators 3:1 (WCAG 1.4.11).
Every row applies to light and dark mode. `--separator` is a decorative hairline and is not used for text; rows are
also separated by spacing and group edges. The `prefers-contrast: more` variant (secondary text becomes primary text)
is not verified on a device.

- Radii have a hierarchy: groups 12, fields 10, monogram tile 8, buttons and chips capsule, sheet top 28. Monograms
  are rounded squares, not circles.
- Shadows only on sheets and popovers. Everything else is separated by surface color (`--surface` on `--bg`).
- Motion shows state only: a sheet appears, a row is pressed, a banner shows up. 150 to 250 ms for state changes,
  340 ms for sheets, 120 ms for press feedback. With `prefers-reduced-motion: reduce` a cross-fade replaces all sliding
  and scaling.

## Layout

- Viewport: `width=device-width, initial-scale=1, viewport-fit=cover`. Never `maximum-scale` or `user-scalable=no`.
- Status bar style is `default`. The content starts below the system bar. `black-translucent` is not used because its
  fixed white text is unreadable on a light background.
- `theme-color` per color scheme equals the page background (not the tint). The manifest `background_color` is the light
  page background so there is no white flash at launch.
- Safe areas come from `env(safe-area-inset-*)`. The bottom bar is 49 px plus the bottom inset. Docked action bars use
  `padding-bottom: max(var(--space-4), var(--safe-bottom))`.
- Use `100dvh`, never `100vh`. Only the content scrolls, the bars stay. `overscroll-behavior: none` on `html, body`,
  `contain` in sheets and lists.
- One 16 px page margin. On wide windows the column is at most 640 px and centered. Landscape must not break.

## Components

Every component has default, pressed, focus (visible), disabled, loading and error states, and looks the same on
every screen.

| Component | Rules |
|---|---|
| Navigation bar | 44 px, large title below that collapses to an inline title on scroll. Back on the left, at most one action on the right. |
| Shop switcher | Left in the navigation bar: stacked monograms plus the current choice and a chevron. Opens a popover menu. The choice applies to all tabs. |
| Tab bar | Five tabs. 24 px icon (filled when selected), `caption-2` label, tint when selected. Badge only on Orders (open to ship, up to 99+). |
| Group (inset list) | `--surface`, radius 12, 16 px margin. Rows are separated by a hairline starting at the text edge. Section titles in `footnote`, `label-2`. |
| Row | At least 56 px (two lines) or 44 px (one line) and grows with Dynamic Type. Monogram left, title and subtitle in the middle, amount or chevron right. Pressed: `--surface-2`. |
| Primary button | Capsule, 50 px, `--tint` with `--tint-ink`, label in `headline`. Disabled is 40 % opacity and a help text says why. |
| Secondary button | Capsule, 50 px, `--tint-soft` with `--tint`. |
| Danger button | Refund confirmation and sign out only: `--danger` with `--danger-on`. The label names the amount. |
| Field | 50 px, radius 10, 1 px `--border-input`, visible label above the field (never placeholder-only), at least 16 px text, error directly below with symbol and text. |
| Segment, chips | Segment for two or three equal views. Filter chips scroll horizontally, 44 px tall, never wrap. |
| Status chip | Capsule, `caption` size, symbol plus text. |
| Sheet | From the bottom, `--sheet` background, fields on `--sheet-field`, top radius 28, grabber, cancel left and action right or docked. Swipe down closes unless an action is running. |
| Toast, banner | Quiet, below the bar, 4 s, with "Undo" where possible. Errors stay until dismissed. |
| Empty state | 40 px symbol, headline, one sentence on what is missing and what to do, one button. |
| Skeleton | Row shape in `--surface-2`, no shimmer, space reserved so nothing jumps. |

Icons are [Phosphor](https://github.com/phosphor-icons/core) 2.1.1 (MIT, license text in `docs/mocks/icons/`), inline
SVG with `fill="currentColor"`: regular in the normal state, fill for the selected tab. Decorative icons get
`aria-hidden="true"`, icons with a function get an `aria-label` or visible text. SF Symbols are not licensed for the
web, so they are not used.

## Dynamic Type and zoom

- All text is in `rem`, line heights are factors, rows use `min-height`, never a fixed height.
- From about 130 % the amount moves below the title. At accessibility sizes chips and monograms wrap and the tab bar
  keeps icon and label (label capped at 1.3 times the base size).
- Nothing clips text. `text-overflow: ellipsis` only for names in single-line rows that have the full text in the
  accessible label. Numbers never wrap.
- Browser zoom stays enabled.
- Verified only at the 17 px default. Larger Dynamic Type sizes are not verified on a device.

## Accessibility

Target is WCAG 2.2 AA and the Apple Human Interface Guidelines.

- Tap targets are at least 44 x 44 pt with 8 px between neighbors. Small icons get invisible padding.
- Color is never the only signal. Status, errors and selection also use text, a symbol or a check mark.
- Focus ring: 2 px `--tint` with 2 px offset (`:focus-visible`). Never `outline: none` without a replacement. Scrolling
  areas have `scroll-padding-bottom` of the bar height so the tab bar does not hide the focused element.
- Rows are one unit with a composed label ("Order 1042, Candle Works, 63.90 euro, to ship, 4 minutes ago"). Tabs use
  `role="tablist"` and `aria-selected`. Sheets are `role="dialog"` with `aria-modal`, and focus moves in and back.
  Changes are announced with `aria-live="polite"`, errors with `role="alert"`. Headings are real `h1` to `h3`.
- Inputs set `autocomplete` (`username`, `current-password`, `one-time-code`), `inputmode="numeric"` for the MFA code
  and `enterkeyhint`, so password managers and the iOS authenticator suggestion work.
- No gesture is the only way to do something. Every swipe action also exists in a menu. Nothing needs press-and-hold.
- `lang` follows the language choice. Numbers and currencies follow the locale.

## Rules for new screens

1. Use tokens only. No raw hex values in components, only `var(--...)`. `build-tokens.mjs --check` reports raw hex in
   the mocks.
2. Reuse the components above. A new control needs a reason that an existing one cannot meet.
3. Write texts in `pwa/src/lib/i18n.ts` for both languages (de and en).
4. Look at the rendered screen, not only at tests: light and dark, 390 px wide, with the iPhone 15 WebKit profile.
   `npm run shots` in `pwa/` writes the screenshots and logs `scrollWidth` against `innerWidth` to
   `docs/shots/overflow-check.json`.
5. Keep three limits: no KPI card grids, no gradient text, no second accent color.

## What is measured and what is not

`npm run mocks` in `pwa/` renders `docs/mocks/*.html` with Playwright WebKit (iPhone 15, light and dark) and writes
`docs/mocks/shots/render-log.txt`: per image `scrollWidth == innerWidth`, every control at least 44 x 44 px, every
input at least 16 px, the computed font family. Not verified because it needs a real iPhone: installation and
standalone launch, real safe-area values, status bar legibility, Dynamic Type, "Increase Contrast", the SF glyph
shapes, push delivery, the camera scan.
